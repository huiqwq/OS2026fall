# Buddy 功能测试

此目录的测试直接使用工程真实 `buddy_pmm.c`、`Page`、页号转换及链表实现，不替换分配算法，不改变精确 n 页分配契约。教师 First-Fit/Best-Fit 测试和评分工具保持原样。

## 运行

在工程根目录执行；宿主测试只需要已有 Python 3 和 GCC，不安装依赖，二进制在临时目录中生成并自动清理：

```sh
python3 tools/buddy_tests/run.py

make clean
make PMM=buddy
timeout 25s make PMM=buddy qemu

make PMM=best_fit clean
make PMM=best_fit
make PMM=best_fit grade
```

更换宿主编译器可用 `python3 tools/buddy_tests/run.py --cc gcc`。切换 PMM 必须清理重编译。QEMU 内核完成初始化后无限循环，因此 timeout 主动结束属预期；通过依据为逐场景 PASS、恢复检查、`check_alloc_page() succeeded!` 和随后的 satp 输出。不能把 timeout 状态 124 当作测试程序正常退出。

## 真实内核中的检查

`buddy_check()` 保留原有只读结构检查为 `buddy_check_invariants()`，增加以下正常功能检查：

- Case 1：同时申请 1、2、4、8、3、5、6、7、9 页，交错释放；每次核对精确增减、物理连续、活跃区间不重叠及所有活跃页的完整内容。
- Case 2：通过公开 `alloc_pages(8)` 取得真实对齐区间。再通过公开接口暂时持有其他空闲标准块，使剩余测试区确实只有这 8 页。申请 5 页后断言尾部为相对第 5 页的单页块及第 6～7 页的双页块；依次再申请 2、1 页，使用不同模式写满并反复校验，耗尽后检查申请失败。
- Case 3：覆盖尾部空闲时释放 5 页后恢复 8 页，以及尾部被占用时不能提前形成 8 页；遍历 5/2/1 三笔申请的全部六种释放顺序。另以单页释放触发同阶和跨阶合并，验证相邻但非伙伴的两个双页块不能合成四页块。
- Case 5：零请求、最大整数请求返回 NULL，页数、合法空闲块组织及活跃数据保持正确；更多边界由宿主独立快照测试覆盖。
- Case 6：固定种子 20261024、128 步申请释放，独立固定记录表追踪活跃区间，逐步检查总量守恒和全部数据。

真实内核测试没有虚构描述符数组，也没有复制或切换真实链表头。测试记录、32 KiB 原始空闲块阶数图为固定参照数据，不依赖被测分配器动态申请。所有实际物理数据写入仅针对公开接口刚返回的页面；暂时持有的外部标准块不写内容。所有暂时持有页面最终以原指针和原长度释放。

恢复时逐块对比测试前的物理起点和阶数，并核对块数、空闲总页数及完整结构不变量。允许链表中合法块的排列顺序变化，不要求恢复没有语义意义的插入顺序。宿主 `kernel-check` 还预先保留一笔外部活跃 5 页分配，检查其数据不受整个内核测试影响。

资源不足时明确打印 SKIP：整体功能测试需要至少一个 64 页标准块，以保证九个基础请求所需的 59 个向上取整页能同时满足；隔离 8 页区间时最多记录 64 个外部空闲块，超过时归还已取得的区间并仅跳过 Case 2/3。SKIP 不会被打印为对应功能用例 PASS。

## 主机夹具与覆盖

`host.c` 在独立进程中建立匹配的全局 `pages`、`npage`、`nbase` 及物理页对应的 backing RAM，通过 `va_pa_offset` 保证同一实现的地址转换成立。不存在将局部假 Page 数组传入真实内核的情况。主机的公开分配释放封装与 `pmm.c` 的转发行为一致，所有请求经 manager 回调进入实际模块。

独立 `registered[]`、`owner[]` 和活跃记录表不从被测元数据推导页面归属。每次结构检查枚举各阶块并逐页覆盖，检查物理对齐、范围、双向关系、每页覆盖恰好一次、保留页/空洞排除和计数守恒。另从独立归属记录预测是否存在满足向上取整请求的对齐标准块，防止随机测试错误接受“有可用标准块却返回 NULL”。完整页模式逐字节复核，既检查越界/重复占用，也检查释放其他分配后原有数据仍保存。

| 场景 | 覆盖 |
| --- | --- |
| normal/basic | 指定九种页数、同时持有、交错释放、精确计数和全页数据 |
| normal/tail | 隔离 8 页、5+2+1、尾部组织和立即复用、耗尽失败 |
| normal/merge | 空闲尾部恢复、六种释放顺序、128 次单页申请后分阶段释放产生连锁合并 |
| normal/non-buddies | 中间相邻的两个双页块物理上不是伙伴，4 页请求须失败；其他两块的数据仍完整 |
| normal/list-ends | 四个分散单页反复入链/出链，检查头尾指针和双向关系；Buddy 实际用 list_add 头插，不存在 First-Fit 式地址排序尾插分支 |
| normal/init-ranges | [3,16)、[35,56)、[64,65)、[0,3) 注册；未对齐、非二次幂、空洞、相邻跨注册合并；逐页申请耗尽并逐页核对合法集合 |
| normal/single | 最小单页注册、分配和释放 |
| normal/maximum | 框架可管理的最大 32768 页池，最高可用阶 15，整块分配释放并恢复 |
| normal/failures | 空池、零请求、超容量、2^31 附近、2^63、最大整数；连续 5 页但无 8 页标准块时允许失败 |
| normal/random | 种子 20261024、2000 步、32 个活跃槽；独立预测可用性、页归属及完整数据检查 |
| normal/kernel-check | 在主机 backing RAM 上执行完整真实 buddy_check，并保护预先存在的活跃分配 |
| normal/kernel-check-small | 仅有一个 64 页块时执行完整内核检查，验证资源门槛不会错误跳过可运行的用例 |

16 类非法操作各在独立进程中执行：空指针、零长度、短长度、长长度、内部指针、重复释放、拼接释放、保留页、未注册页、数组下界外、数组上界外、未按描述符对齐指针、巨大长度、重叠注册、零注册、越界注册。开始操作前完整保存描述符数组、每阶链表头、计数和初始化状态；预期 panic 仅在来自实际 Buddy 模块、上述状态逐字节未变且所有活跃数据完整时算通过。测试自身断言不能冒充预期拒绝。所有场景独立运行，某项失败不阻止后续场景。

另有 9 个结构故障注入进程：NULL 链接、错误 prev 链接、错误计数、错误块大小、未对齐块、块内混入占用页、重叠块、未合并伙伴及漏挂空闲块。均要求真实不变量检查拒绝，且不修改故障现场。它们验证测试确实能够发现对齐错误、错误合并、重复覆盖、泄漏和计数错误。

## 本轮结果和验证边界

实际输出见 `logs/`。本轮发现的算法缺陷：无；分配、释放、注册、切分、合并及元数据契约未修改，只扩充检查与测试。

正常主机用例 12 项、预期拒绝 16 项、故障注入 9 项，共 37 项；结果及 PMM=best_fit 的评分以保存日志为准。原评分明确要求 Best-Fit，不用于宣称 Buddy 正确。

未运行：真机、多核并发、穷尽全部申请释放排列；预期 panic 场景未逐项放入 QEMU，而是在独立主机进程执行。初始化边界及最大可用阶数测试也在主机完成。2^31/2^63 等超大请求受真实管理容量约束，会在容量检查处拒绝；没有伪造巨大的 nr_free 来强行执行在本框架不可达的移位保护分支。资源不足的 SKIP 分支尚未人为触发，本轮默认配置没有跳过正常内核用例。
