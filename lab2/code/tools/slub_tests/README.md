# 简化 SLUB 功能与边界测试

在工程根目录执行。宿主驱动直接编译实际 `slub.c` 和所选实际 PMM，使用工程真实 Page/链表/地址转换；不是另写的分配算法模型。仅编译到临时目录，不安装依赖，不修改教师工具。

```sh
# 全部独立主机场景（每种 PMM 31 项，共 62 项）
python3 tools/slub_tests/run.py
# 只选择正常、OOM 或非法调用，不把 panic 放进正常启动路径
python3 tools/slub_tests/run.py --group normal --pmm buddy
python3 tools/slub_tests/run.py --group oom --pmm both
python3 tools/slub_tests/run.py --group invalid --pmm both

make clean
make PMM=buddy SLUB_TEST=1
timeout 45s make PMM=buddy SLUB_TEST=1 qemu
make PMM=best_fit SLUB_TEST=1 clean
make PMM=best_fit SLUB_TEST=1
timeout 45s make PMM=best_fit SLUB_TEST=1 qemu

# 原评分是 Best-Fit 验收，与上述扩展正常测试分别运行
make PMM=best_fit SLUB_TEST=0 clean
make PMM=best_fit SLUB_TEST=0
make PMM=best_fit SLUB_TEST=0 grade
```

`--cc` 可选择已有宿主编译器。切换配置必须清理重编译。QEMU 初始化完成后内核无限循环，命令由 timeout 主动结束；退出 124 不是正常结束，通过依据是各场景 PASS、ALL NORMAL PASS、恢复的基线及最后空 SLUB 结构摘要。`SLUB_TEST=0` 不调用启动自检，也不编译功能测试参照数组/辅助函数。

## 正常内核自检

原有只读结构断言保留为 `slub_check_invariants()`。`slub_check()` 在 SLUB_TEST=1 时调用固定参照数据支持的正常功能用例；初始化、kmalloc、kfree、布局和回收算法未修改。

| 用例 | 实际覆盖 |
| --- | --- |
| Case 1 | 1、15、16、17、31、32、33、63、64、65、127、128、129、255、256、257、511、512、513、1023、1024、1025、2047、2048、2049；同时持有，核对最小类别、16 字节对齐、槽位范围及完整请求数据 |
| Case 2 | 4095、4096、4097、8192、8193、16385；同时持有并交错释放，页数独立按除法及余数计算；特别检查 16385 为 5 页，跨页与末尾均写入复查 |
| Cases 3/4 | 每个类别由实际 sizeof(slab) 和对齐计算容量；申请 capacity+1 个对象跨两页；满 slab 释放后转 partial，再申请只需已有空位、不要求相同地址；按偶数/奇数序交错释放，逐次判断是否最后一个对象 |
| Case 5 | 种子 20261024，384 步，16 个活跃槽，混合小类别和最多 3 页大对象，反复分配/局部回收/复用/全部清理 |
| Case 6 正常部分 | kmalloc(0)、kfree(NULL)、最大整数、取整溢出临界两侧、超容量，保留现有对象并复查数据；OOM 另由独立主机场景验证 |
| Case 7 | 每个对象检查所有权和物理连续页记录；Buddy 下同时校验注册/空闲位、PageProperty 和首 property 的原始长度；归还后仅访问描述符，不再读 slab 页头 |

容量为 1 的 2048 类别不能在仍有对象时成为 partial，测试按“full → 立即归还 → 重新申请页”判断，不把空 slab 常驻当作契约。

参照记录为静态数组，不用 kmalloc 自举。每次操作都复核所有活跃请求的逐字节确定性模式、区间不重叠、分配位、元数据和独立页数模型。新增一个 slab 才扣一页；同页后续对象不扣页；释放最后一个对象才加一页。全部页数由活跃记录推导，不用分配器自己的计数当参照答案。全局原结构检查每 16 步及关键状态转换/场景结束执行，检查链表双向关系、full/partial、freelist 无环无重复、位图互补、所有权与下层状态。

写入负载前先验证完整页面所有权、下层长度、对象区边界和槽位几何，避免测试在分配器返回错误地址时先覆盖管理信息或其他页面。数据模式写满请求范围；等于类别的请求写满整个槽位。这样可检出对象重叠、错误偏移/容量、管理数据覆盖和其他申请释放造成的数据损坏。

每次释放前从独立活跃表计算该页仍有多少对象，据此断言准确的页数变化。大对象按请求推导原始 n，主机页接口还独立记录原始 Page* 和 n，任何部分、内部或扩大释放都会由驱动失败。配合最终空闲基线、空 cache/所有权扫描，可检出错误页释放、常驻空 slab、泄漏及悬挂节点。

测试资源全部经公开分配接口取得。没有浅拷贝链表头、重置真实分配器或改写页管理器私有状态。正常自检要求空的受控 SLUB 上下文，并先合法申请/释放 64 页探测块；上下文已有活跃 SLUB 对象或探测失败时明确打印 SKIP，不打印 ALL NORMAL PASS。本轮启动环境没有跳过任何正常用例。

## 独立主机场景

每种 PMM 分别执行以下 31 项，每项单独进程；单项失败不阻止后续项。

- 2 项完整正常自检：空上下文；同时存在一笔普通页分配器的 3 页分配，确认其数据与元数据不受 SLUB 测试影响。结束后通过原 manager.check 回调执行下层自检。只在该教师自检期间暂停 SLUB 专用的“必须整笔释放”观察器，因为 Best-Fit 教师自检本来就包含合法的部分释放；没有跳过或修改其断言，也没有改写私有链表。
- 2 项 OOM：新 slab 的 1 页申请失败；大对象的 5 页申请失败。注入在真正的 alloc_pages 页接口，而非 kmalloc 包装器提前返回。测试确认 free pages 足够、目标 cache 无可用 partial、请求实际到达接口、调用次数增加且 n 分别为 1/5。对同一已有 partial 的申请不会消耗注入，随后新页请求才触发故障。关闭故障后可继续申请并按原 n 释放，最终恢复基线。
- 1 项失败快照：保留活跃小/大对象时，对零值、最大整数、取整边界、超容量和 NULL 释放比较完整状态。
- 14 项非法调用：初始化前申请、初始化前非空释放、重复初始化、小对象内部指针、动态选取的未分配槽位、同 slab 仍在用时重复释放、整 slab 已回收时重复释放、普通页、保留页、映射下界外、上界外、大对象内部偏移、内部页面、重复大对象释放。
- 12 项结构故障：链接损坏、freelist 越界、freelist 循环、freelist 指向在用对象、位图损坏、容量错误、偏移错误、inuse 错误、错误 partial/full 归属、内部页所有权丢失、原始大对象页数错误、下层页状态错误。

主机建立自己的全局 pages/npage/nbase 和 128 页匹配 backing RAM，4 页保留，未把局部假描述符传给真实内核地址转换。全部 PMM/SLUB 逻辑来自工程文件。宿主只提供控制台、独立进程、页接口故障注入和观察记录，不模拟另一个 SLUB 算法。

失败或预期 panic 前保存完整 RAM、描述符、cache、计数、所有权、下层链表和原始页请求记录；只有实际 slub.c 抛出断言且上述状态逐字节未变才算预期拒绝。测试自身的断言或意外崩溃不会算通过。故障注入的控制计数属于驱动，按预期消耗一次；分配器状态必须不变。

## 结果与边界

实际结果和命令见 `logs/host.log`、`logs/qemu-buddy-on.log`、`logs/qemu-best-fit-on.log`、`logs/grade-best-fit.log`、`logs/commands.txt`。这些是执行后的日志，不是测试计划。旧评分只报告 PMM=best_fit 的结果，不代表 SLUB 功能验收。

本轮没有发现需要修复的分配算法缺陷。新增测试不改变空 slab 立即归还、非法释放拒绝或精确页数契约，不改 Buddy、Best-Fit、教师测试和评分工具。

未执行：真机、多核、穷尽所有申请释放顺序；未把每个预期 panic/结构损坏场景逐项放入 QEMU。OOM 使用受控页接口故障注入，没有耗尽真实内核 RAM。资源不足和非空 SLUB 的 SKIP 分支尚未人为触发。本轮不要求识别地址已被合法复用后的历史指针，也不假设新对象内容为零。
